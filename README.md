# MLOps: версии данных и сравнение моделей Wine

Репозиторий содержит практики 3 и 4. В третьей работе Iris и Wine версионируются через DVC и ClearML Dataset. В четвёртой шесть конфигураций Logistic Regression и Random Forest сравниваются в MLflow, а лучший результат сохраняется в ClearML.

Результаты, идентификаторы и объяснение выбора модели находятся в [REPORT.md](REPORT.md). Автоматические проверки последней серии — в [verification.json](verification.json).

## Окружение

Требуются Python 3.12, Git, Poetry и доступ к ClearML. Из корня репозитория:

```powershell
poetry env use 3.12
poetry install
poetry run python --version
poetry run python -m pip check
```

Версии зависимостей фиксируются в `poetry.lock`. На исходном компьютере готовое окружение расположено в `../.venv`. Его можно использовать, активировав `..\.venv\Scripts\Activate.ps1` перед командами Poetry.

Подключение ClearML настраивается командой `clearml-init`. Файл `clearml.conf` и API-ключи должны оставаться вне Git. Если подключение уже настроено, повторная настройка не нужна.

## Восстановление данных практики 3

```powershell
poetry run dvc pull
poetry run python check_data.py --version merged
```

DVC remote настроен на соседнюю папку `../dvc_remote_Gubeev`, расположенную вне репозитория. На другом компьютере нужно отдельно получить это хранилище либо настроить доступное сетевое хранилище командой `poetry run dvc remote modify --local storage <путь>`. Один Git clone не переносит содержимое DVC remote.

Скрипты `clearml_versions.py`, `clearml_wine.py` и `clearml_iris_features.py` выводят сведения о трёх версиях. С флагом `--execute` они получают и проверяют существующие версии по сохранённым ID. Для скачивания всех версий используется `download_clearml_versions.py`, для проверки — `verify_clearml.py`.

## MLflow Tracking Server

Запустите в отдельном терминале из корня проекта:

```powershell
poetry run mlflow server --backend-store-uri sqlite:///mlflow.db --host 127.0.0.1 --port 8081
```

Интерфейс и API доступны по адресу [http://127.0.0.1:8081](http://127.0.0.1:8081). SQLite хранит параметры, метрики и сведения о запусках; файлы моделей находятся в отдельном хранилище артефактов MLflow. Сервер работает, пока открыт терминал; остановка — `Ctrl + C`.

## Эксперименты практики 4

В другом терминале с активированным окружением:

```powershell
poetry run python run_experiments.py `
  --dataset-id fd4384d1b03242269ec15a584a543499 `
  --expected-sha256 b72adfd45219c12d4af882f76b4c67df0a44922d0bac0f2fd30e4b8d0c97a301 `
  --tracking-uri http://127.0.0.1:8081 `
  --clearml --update-report
```

`--clearml` создаёт Task `MIIT/MLOps/practice_4/Gubeev / wine-best-model` и публикует OutputModel. `--update-report` обновляет раздел «Эксперименты» в общем отчёте.

Для выполнения только MLflow-части уберите `--clearml`. Работа без Tracking Server доступна с `--tracking-uri sqlite:///mlflow.db`. Адрес также можно передать переменной окружения `MLFLOW_TRACKING_URI`.

Скрипт получает Wine по ID, проверяет SHA-256, создаёт один стратифицированный split 60/20/20 и обучает три Logistic Regression (`C=0.1, 1, 10`) и три Random Forest. У всех запусков одинаковые метрики и теги происхождения данных. Отдельный `session_id` отделяет текущую шестёрку от предыдущих запусков.

В MLflow используется формат `skops`. Для созданных скриптом Random Forest явно разрешён тип `sklearn.tree._tree.Tree`; список сохраняется в метаданных модели.

Победитель выбирается по validation F1. При равенстве используется алфавитный порядок имён конфигураций. После выбора загружается сохранённая модель, проверяются её предсказания и один раз вычисляются метрики test. Неполное логирование, несовпадение хэша или ошибка проверки завершают скрипт с ненулевым кодом.

Повторное выполнение создаёт шесть новых runs в том же experiment. Предыдущие результаты сохраняются. `verification.json` и раздел отчёта с флагом `--update-report` относятся к последнему успешному выполнению.

## Результаты и проверки

В `artifacts/practice_4/<session_id>/` сохраняются таблица сравнения, индексы split, версии библиотек, модель, предсказания test, матрица ошибок и метрики по классам. Эти файлы также прикрепляются к соответствующим запускам MLflow и результату ClearML. Локальные базы, кэши и файлы моделей исключены из Git.

После выполнения экспериментов:

```powershell
poetry run python -m unittest discover -s tests -v
```

Тесты проверяют отклонение файла с неверным хэшем, шесть завершённых runs, разные конфигурации, одинаковую версию данных и split, изоляцию текущей серии и наличие test-метрик только у победителя.

## Доступ для проверки в ClearML

Ссылки на Task, модель и Dataset находятся в REPORT.md. Для просмотра из другого workspace ClearML Hosted откройте страницу Task, выберите меню **Share → Create link** и передайте преподавателю созданную ссылку. Она предоставляет чтение Task и связанных материалов, включая модель. Для исходных версий Dataset аналогично откройте их служебные Task и создайте ссылки чтения.

`OutputModel.publish()` фиксирует модель в состоянии Published. Создание ссылки чтения — отдельная операция в интерфейсе Hosted Service; стандартный SDK не выполняет её в этом проекте.

Демонстрация преподавателя на Breast Cancer находится в `notebooks/experiments_demo.ipynb`. Она выполняется отдельно от самостоятельной работы Wine; результаты демонстрации не участвуют в выборе модели.
